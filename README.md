# hh-pars

Telegram-бот (`@ggparswolstbot`), который по пресетам пользователей собирает вакансии
с hh.ru и Хабр Карьеры и присылает новые в чат.

Стек: Python 3.12, aiogram 3, httpx, SQLAlchemy (async) + PostgreSQL, APScheduler, Docker.

## Источники

- **hh.ru** — HTML-страница поиска, ищет по названию вакансии. JSON API (api.hh.ru) отдаёт 403
  анонимам с датацентровых IP, поэтому не используется.
- **Хабр Карьера** — JSON страницы `/vacancies` (`/api/frontend/vacancies`), фильтры по id:
  специализация, навык, грейд, город. Официальный API Хабра — только для работодателей.
  Площадка небольшая (~1,8 тыс. вакансий), это добавка к hh.ru. Соответствие кодов пресета
  и id Хабра — словари `HABR_*` в [src/bot/keyboards.py](src/bot/keyboards.py). Отключается
  `HABR_ENABLED=false`.

Особенности:

- одна и та же вакансия на обеих площадках приходит один раз: повтор с другой площадки
  узнаётся по названию и компании среди найденного за 30 дней;
- у пресетов, заведённых до подключения площадки, её первая выдача сохраняется без рассылки
  (видна в Excel-отчёте), дальше — как обычно;
- «Вся Россия» на Хабре ищет без города (такого фильтра там нет), стаж hh.ru переведён в
  грейды примерно, а при выбранном опыте вакансии без грейда (~15% на Хабре) не попадают.

## Отклики (только владелец)

Владельцу бота (`OWNER_TELEGRAM_ID`) под каждой новой вакансией приходят кнопки
«✅ Подтвердить» — откликнуться от его имени — и «❌ Отклонить». Итог дописывается в сообщение,
кнопки убираются; в Excel-отчёте — колонка «Решение». Остальные пользователи видят вакансии
как раньше.

Настройка — пункт меню «⚙️ Отклики»:

- **вход** — cookies браузерной сессии hh.ru / Хабр Карьеры: владелец копирует их из браузера
  (расширение Cookie-Editor → Header String / JSON или заголовок `Cookie` из DevTools) и
  присылает боту текстом или файлом. Бот сразу удаляет это сообщение, проверяет вход и хранит
  cookies зашифрованными (Fernet, ключ `SESSION_ENCRYPTION_KEY`). Обновлённые сайтом cookies
  сохраняются после каждого запроса; истёк вход — бот так и скажет, cookies присылаются заново;
- **резюме hh.ru** — со страницы «Мои резюме»; на Хабре резюме — профиль, выбирать нечего;
- **шаблон письма** — с подстановкой `{вакансия}` и `{компания}`; пустой — отклик без письма.

Как устроено ([src/apply/](src/apply/)): API соискателя ни у hh.ru (OAuth физлицу не дают), ни у
Хабра нет, поэтому бот повторяет запросы веб-интерфейса сайтов через тот же RU-прокси:

- **hh.ru** — `GET` и `POST /applicant/vacancy_response/popup` (поля формы восстановлены по
  сайту); после «успеха» бот ищет вакансию в списке откликов и предупреждает, если не нашёл;
- **Хабр Карьера** — CSRF-токен `GET /api/frontend_v1/users/authenticity_token`, отклик
  `POST /api/frontend/vacancies/<id>/responses` с `{"body": письмо}`; перед ним бот смотрит
  SSR-состояние страницы вакансии: вход, архив, вопросы работодателя, заглушку вместо формы.

Вакансии с вопросами работодателя, тестом или капчей бот не отправляет — пишет, что
откликнуться нужно на сайте.

## Структура

```
src/
  config.py        # настройки из .env (pydantic-settings)
  sources.py        # площадки: метки, префиксы id
  hh_client.py      # парсер страницы поиска hh.ru
  habr_client.py    # клиент поиска Хабр Карьеры
  parser.py         # логика поиска новых вакансий и сохранения в БД
  apply/            # отклики от имени владельца: cookies, hh.ru, Хабр Карьера
  bot/apply.py      # меню «⚙️ Отклики» и кнопки под вакансией
  bot/handlers.py   # хендлеры aiogram
  storage/          # SQLAlchemy модели + подключение к БД
  main.py           # точка входа: бот + планировщик
tests/
.github/workflows/  # CI и CD
```

## Быстрый старт

```bash
cp .env.example .env   # заполнить токены
docker compose up --build
```

## Переменные окружения

См. [.env.example](.env.example):

- `HH_CLIENT_ID` / `HH_CLIENT_SECRET` / `HH_ACCESS_TOKEN` — нужны только если требуется
  доступ к приватным данным hh.ru API (обычный поиск вакансий работает без токена, но требует `HH_USER_AGENT`).
- `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` — бот и чат для уведомлений.
- `DATABASE_URL` — строка подключения к PostgreSQL.
- `HH_PROXY_URL` — прокси для запросов к hh.ru и Хабр Карьере (на главном узле — SOCKS RU-ноды).
- `HABR_ENABLED` — искать ли ещё и на Хабр Карьере (по умолчанию `true`).
- `OWNER_TELEGRAM_ID`, `SESSION_ENCRYPTION_KEY` — отклики владельца (см. «Отклики»);
  `BROWSER_USER_AGENT` — User-Agent запросов от его имени.
- `TELEGRAM_PROXY_URL` — прокси к Telegram API, только где он заблокирован.
- `PARSE_INTERVAL_MINUTES`, `HH_SEARCH_TEXT`, `HH_SEARCH_AREA` — параметры парсинга.

## CI/CD

### CI (`.github/workflows/ci.yml`)

На каждый push/PR в `main`: линт (ruff), тесты (pytest), пробная сборка Docker-образа.
Выполняется на обычных github-hosted раннерах, публикации никуда не делает.

### CD (`.github/workflows/cd.yml`)

На каждый push в `main` (и тег `v*`):

1. `build-and-push` собирает образ и пушит в GHCR: `ghcr.io/ggwolst/hh-pars:latest` и `:<sha коммита>`.
2. `deploy` заходит по SSH на главный узел и запускает там `deploy.sh` с образом этого коммита.

Деплой включается переменной репозитория `DEPLOY_ENABLED=true` и секретами
`SSH_HOST`, `SSH_PORT`, `SSH_USER`, `SSH_KEY`, `SSH_FINGERPRINT`. Без них job пропускается,
образ всё равно собирается.

## Деплой (главный узел)

Бот живёт на главном узле инфраструктуры, а не в локальной сети:

- приложение — `/root/hh-pars`: `docker-compose.prod.yml` (копия из репо) и `.env` (секреты, не в git).
  В `.env` заданы `COMPOSE_FILE=docker-compose.prod.yml` и `HH_PARS_IMAGE` — поэтому
  `docker compose ps/logs/up` там работают без `-f`;
- Telegram — напрямую (WARP, как на старом сервере, не нужен);
- hh.ru и Хабр Карьера — через SOCKS5 RU-ноды: `HH_PROXY_URL=socks5://17.9.7.5:1080` (доступ с главного узла
  разрешён на стороне ноды);
- `deploy.sh` — копия [deploy/server-deploy.sh](deploy/server-deploy.sh) в `/root/scripts/hh-pars/`,
  принудительная команда ключа деплоя в `authorized_keys` (`command=…,restrict`): ключ из
  GitHub не даёт shell и умеет только обновить образ сервиса `bot`. Журнал — `deploy.log` рядом.

Что обновляет CD, а что — руками:

- образ бота — CD;
- `docker-compose.prod.yml` и `.env` — руками (скопировать на сервер, `docker compose up -d`);
- сам `deploy.sh` — руками (CD его не трогает).

Откат на прежний образ (они остаются на диске):

```bash
cd /root/hh-pars
sed -i 's|^HH_PARS_IMAGE=.*|HH_PARS_IMAGE=ghcr.io/ggwolst/hh-pars:<sha>|' .env
docker compose up -d bot
```

Подробности и откат всей установки — `/root/scripts/hh-pars/README.md` на сервере.
